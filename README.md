# 읽기 가속기

붙여넣은 글을 어절 단위로 한 자리에 흘려보내는 **RSVP**, 어근 앞부분만 굵게
세우는 **바이오닉 리딩**. 이동 중 자투리 시간에 전공 자료를 훑는 용도.

링크 하나만 주면 각자 폰에서 쓸 수 있다. 서버에 저장되는 것이 없다.

## 구조

```
reader.html            리더 본체 — 여기만 고치면 된다 (의존성 0)
build.py               reader.html → index.html + 아이콘 + 매니페스트 + sw.js
index.html             배포본 (생성물, 커밋해야 Pages 가 서빙한다)
manifest.webmanifest   생성물 — 홈 화면 추가용
sw.js                  생성물 — 오프라인 캐시
icon-*.png             생성물
app.py                 로컬에서 띄워 볼 때 쓰는 Streamlit 껍데기 (선택)
```

리더를 고친 뒤에는 **반드시** 다시 빌드한다. `index.html` 은 생성물이라
직접 고치면 다음 빌드에 덮어써진다.

```bash
pip install pillow
python build.py
```

## 배포 — GitHub Pages

```bash
git remote add origin https://github.com/<내-아이디>/<저장소>.git
git push -u origin main
```

저장소 → **Settings → Pages → Source: Deploy from a branch → `main` / `(root)`**
→ 저장. 1~2분 뒤 `https://<내-아이디>.github.io/<저장소>/` 가 열린다. 그 주소를
친구들에게 주면 끝이다.

무료 플랜에서 Pages 를 쓰려면 저장소가 **public** 이어야 한다. 공개되는 것은
앱 코드뿐이고, 각자 읽는 글은 서버로 가지 않는다. 저장소를 비공개로 두고 싶으면
Cloudflare Pages 가 무료로 private 저장소 배포를 지원한다.

**친구들에게 같이 알려 줄 것** — 주소를 연 뒤 브라우저 메뉴에서 *홈 화면에 추가*
를 하면 앱처럼 열리고, 한 번 연 뒤에는 신호가 없어도 동작한다.

### 왜 Streamlit 이 아닌가

Streamlit Community Cloud 는 컨테이너가 하나라서 (1) 한동안 아무도 안 들어오면
잠들고 다시 깨는 데 30초쯤 걸리고, (2) 누가 큰 PDF 를 올리면 그동안 다른 사람도
느려진다. 리더는 서버가 할 일이 없는 구조라 정적 호스팅이 더 빠르고 안 잠든다.
`app.py` 는 로컬에서 쓰고 싶을 때를 위해 남겨 뒀다.

## 각자 폰에서 겹치지 않는 이유

읽던 위치·속도·굵기·축 색·용어·지문은 전부 **그 브라우저의 `localStorage`** 에만
들어간다. origin 단위로 격리되므로 사람마다, 기기마다 따로 관리된다. 서버는
파일을 내려주기만 하고 아무것도 받지 않는다.

- 같은 폰에서 같은 브라우저 프로필을 두 사람이 쓰면 그때는 공유된다 (유일한 예외).
- 시크릿 창에서는 창을 닫는 순간 사라진다. 저장이 막혀도 리더는 정상 동작한다.
- 폰과 PC 는 서로 넘어가지 않으므로 이어 읽기가 기기별로 따로 간다.
- `.md` 파일도 브라우저 안에서 읽는다. 파일이 업로드되지 않는다.
- 프롬프트 서랍에 적은 `[입력 데이터]` · `[output]` 도 그 브라우저에만 남는다.

## 조작

| | |
|---|---|
| 화면 탭 / `Space` | 재생·정지 |
| `←` `→` | 어절 이동 |
| `↑` `↓` | 속도 ±20 |
| `R` | 이 문장 처음으로 |
| `[` `]` | 단락 이동 |
| `1` `2` `3` | 묶음 어절 수 |
| `Home` | 맨 앞 |

폰에서는 화면 탭으로 재생·정지, 아래 버튼 줄과 본문 어절 탭으로 이동한다.

## 설정

- **속도** — 분당 어절. 250 안팎에서 시작해 내용이 따라올 때마다 20씩 올린다.
- **묶음** — 한 번에 띄우는 어절 수. 정의·공식은 1어절, 설명문은 2~3어절.
- **굵기** — 조사를 떼어낸 어근 앞부분만 굵게. 끄기/약/중/강.
- **체류** — 문장 끝·쉼표, 긴 단어, 영문 용어와 숫자, 괄호, 단락 첫머리에서 자동 감속.
- **축 색** — 가운데 고정되는 축 글자 색. 빨강이 기본이고, 오래 봐서 피로하면 청록이 차선.
- **용어** — 쉼표로 적어 두면 본문에 형광으로 남고, 지날 때 더 오래 머무른다.

오른쪽 가장자리의 **프롬프트** 탭에 전공 PPT 를 줄글로 바꾸는 프롬프트가 들어 있다.

## 전공 PPT 는 줄글로 바꿔서 넣는다

PPT 는 토막 난 명사구라 그대로 읽으면 속독이 걸리지 않는다. 오른쪽 **프롬프트**
탭을 열면 전공책 문체의 줄글로 바꿔 오는 프롬프트가 들어 있다. Claude 에 PPT 를
올리고 그 프롬프트를 함께 보낸 뒤, 나온 글을 지문 칸에 붙여넣는다.

프롬프트의 `[입력 데이터]`(무엇을 어디까지)와 `[output]`(결과를 어디로)은 사람마다
다르므로 서랍 안의 두 칸에 직접 적는다. 적은 내용은 복사본에 그대로 반영되고
브라우저에 저장된다.

PDF 업로드는 뺐다. 추출 결과의 단락·표·각주가 뒤섞여 원문보다 읽기 나빠지는 경우가
많아서, 줄글로 정리된 글을 넣는 쪽이 낫다. `.md` 파일 열기는 남겨 뒀다
(UTF-8 실패 시 cp949 로 재시도).

## 글자 크기가 프레임마다 튀지 않는 이유

어절 길이는 들쭉날쭉한데 프레임마다 크기를 다시 정하면 글자가 튄다. 그래서
지문을 넣을 때 **묶음 길이의 95백분위**로 기준 크기를 한 번만 정하고, 그보다
긴 드문 묶음만 그 자리에서 줄인다. 칸 높이는 기준 크기만 반영하므로 재생 중에는
높이가 변하지 않는다.
